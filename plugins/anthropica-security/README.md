# Security pack (`anthropica-security`)

> Generated by `scripts/build.py` from `packs.json`. Do not edit files in this folder; edit `skills/`, `agents/` or `packs.json` and rebuild.

For: Application, cloud and product security teams. Security reviews, threat modeling, supply-chain security, repository governance and incident response.

## Install

```text
/plugin marketplace add jamal-gml/anthropica
/plugin install anthropica-security@anthropica
```

Claude loads a skill automatically when a task matches its description. Invoke one directly with its slash command.

## Skills

| Command | Use it for |
|---|---|
| `/anthropica-security:security-review` | Review application changes for authentication, authorisation, input validation, secrets, injection and common security weaknesses. Use when a change touches authentication, user input, secrets, file handling or external integrations. |
| `/anthropica-security:threat-modeling` | Threat-model a system, feature or architecture change (data flows, trust boundaries, STRIDE threats, risk rating, mitigations) before or during design. Use when designing a feature that handles authentication, payments, personal data, file uploads, external integrations or new infrastructure, or when a security design review is requested. |
| `/anthropica-security:supply-chain-security` | Assess and harden software supply-chain security (dependency vulnerabilities, lockfiles, pinning, SBOMs, artifact signing and provenance, CI/CD hardening, secret exposure). Use when auditing dependencies, triaging Dependabot or scanner alerts, adding a new dependency, or hardening build and release pipelines. |
| `/anthropica-security:github-repo-governance` | Set up or audit GitHub repository governance (rulesets and branch protection, CODEOWNERS, required checks, Dependabot, secret scanning, code scanning, environments, templates). Use when creating a repository, hardening an existing one, or reviewing repository settings against a team standard. |
| `/anthropica-security:github-actions` | Author, harden and debug GitHub Actions workflows (least-privilege permissions, SHA-pinned actions, OIDC instead of long-lived secrets, caching, concurrency, environments, reusable workflows). Use when creating or editing files in .github/workflows, or when a workflow run fails. |
| `/anthropica-security:incident-response` | Run or support an incident from detection through mitigation, communication and a blameless postmortem. Use when production is degraded or down, an alert is firing, a security event is suspected, or a postmortem or runbook needs writing. |
| `/anthropica-security:infrastructure-as-code` | Write, review and apply infrastructure as code (Terraform/OpenTofu, Bicep, Pulumi, CloudFormation) safely, with plan-before-apply, remote state, modules, policy checks and drift control. Use when changing cloud resources, networking, IAM or IaC modules, or reviewing a plan. |
| `/anthropica-security:codebase-analysis` | Map relevant architecture and trace a requested behaviour in an unfamiliar repository. Use before broad or cross-module changes. |
| `/anthropica-security:token-efficiency` | Reduce unnecessary Claude context and output while preserving correctness. Use when planning a Claude session, reducing token use, managing context, splitting work, or improving prompt efficiency. |
| `/anthropica-security:prompt-engineering` | Create precise prompts and task specifications for Claude and coding agents. Use when a task is ambiguous, complex, multi-stage, or needs clear acceptance criteria and bounded scope. |
| `/anthropica-security:technical-documentation` | Write or update concise technical documentation, setup guides, architecture notes and operational runbooks. Use when writing READMEs, setup guides, architecture notes or runbooks. |

## Agents

| Agent | Role |
|---|---|
| `security-reviewer` | Reviews code and configuration for realistic vulnerabilities and trust-boundary failures. Use when a change touches authentication, authorisation, user input, secrets, file handling, dependencies or infrastructure config. |
| `code-reviewer` | Reviews a diff for correctness, regressions, maintainability and test gaps. Use after a change is implemented and before it is committed or merged. |
