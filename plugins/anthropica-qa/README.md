# Quality assurance pack (`anthropica-qa`)

> Generated by `scripts/build.py` from `packs.json`. Do not edit files in this folder; edit `skills/`, `agents/` or `packs.json` and rebuild.

For: QA engineers and testers. Risk-based test plans, test cases, bug reports, automated testing and release readiness.

## Install

```text
/plugin marketplace add jamal-gml/anthropica
/plugin install anthropica-qa@anthropica
```

Claude loads a skill automatically when a task matches its description. Invoke one directly with its slash command.

## Skills

| Command | Use it for |
|---|---|
| `/anthropica-qa:test-planning` | Create risk-based test plans, test cases, exploratory test charters and high-quality bug reports for features and releases. Use when planning QA for a feature or release, writing test cases from requirements, organising regression testing, or reporting a defect. |
| `/anthropica-qa:testing-validation` | Design and run focused unit, integration, end-to-end and regression checks for a requested change. Use after implementing a change, or when tests are missing, flaky or failing. |
| `/anthropica-qa:release-readiness` | Prepare a release readiness review covering changes, tests, migrations, security, rollback and deployment approvals. Use before tagging, promoting or deploying a release. |
| `/anthropica-qa:performance-investigation` | Investigate measured performance, latency, memory, database or frontend bottlenecks without speculative optimisation. Use when something is slow or memory-heavy and the cause has not been measured yet. |
| `/anthropica-qa:codebase-analysis` | Map relevant architecture and trace a requested behaviour in an unfamiliar repository. Use before broad or cross-module changes. |
| `/anthropica-qa:ui-ux-review` | Review screens, flows, mockups or built UI for usability, accessibility (WCAG 2.2 AA), visual consistency and content clarity, with prioritised, actionable findings. Use when critiquing a design, checking a page before launch, or auditing accessibility. |
| `/anthropica-qa:github-pull-requests` | Create, review and merge GitHub pull requests to industry standard (branch naming, small focused PRs, clear descriptions, CI gates, review etiquette, merge strategy). Use when starting a branch, opening or updating a PR, responding to review, or merging. |
| `/anthropica-qa:token-efficiency` | Reduce unnecessary Claude context and output while preserving correctness. Use when planning a Claude session, reducing token use, managing context, splitting work, or improving prompt efficiency. |
| `/anthropica-qa:prompt-engineering` | Create precise prompts and task specifications for Claude and coding agents. Use when a task is ambiguous, complex, multi-stage, or needs clear acceptance criteria and bounded scope. |
| `/anthropica-qa:technical-documentation` | Write or update concise technical documentation, setup guides, architecture notes and operational runbooks. Use when writing READMEs, setup guides, architecture notes or runbooks. |

## Agents

| Agent | Role |
|---|---|
| `test-engineer` | Designs, writes and runs focused tests for changed behaviour, regressions and edge cases. Use after implementing a change or when tests are missing, flaky or failing. |
| `code-reviewer` | Reviews a diff for correctness, regressions, maintainability and test gaps. Use after a change is implemented and before it is committed or merged. |
