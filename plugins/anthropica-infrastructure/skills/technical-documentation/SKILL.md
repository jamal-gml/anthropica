# Technical Documentation

- Verify commands, paths, environment variables and architecture from the repository.
- Write for the intended operator or developer.
- Put quick-start steps before deep reference material.
- Keep secrets and sensitive values out of examples.
- Prefer links to canonical detailed references over duplicated content.
- Update only documentation affected by the change.
- Mark unknown or unverified details as TODO rather than inventing them.
