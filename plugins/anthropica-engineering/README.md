# Software engineering pack (`anthropica-engineering`)

> Generated by `scripts/build.py` from `packs.json`. Do not edit files in this folder; edit `skills/`, `agents/` or `packs.json` and rebuild.

For: Backend, frontend and full-stack developers. Codebase analysis, backend, frontend, database, testing and GitHub workflow standards.

## Install

```text
/plugin marketplace add jamal-gml/anthropica
/plugin install anthropica-engineering@anthropica
```

Claude loads a skill automatically when a task matches its description. Invoke one directly with its slash command.

## Skills

| Command | Use it for |
|---|---|
| `/anthropica-engineering:codebase-analysis` | Map relevant architecture and trace a requested behaviour in an unfamiliar repository. Use before broad or cross-module changes. |
| `/anthropica-engineering:architecture-design` | Design or evaluate software architecture, system boundaries, technology choices and implementation plans. Use when planning a new application, major feature, migration or architectural change. |
| `/anthropica-engineering:project-bootstrap` | Establish a new or existing software project for Claude with concise instructions, conventions, quality gates and optional skills. Use when starting a project, onboarding Claude to a repository, or creating CLAUDE.md/AGENTS.md. |
| `/anthropica-engineering:backend-development` | Implement backend services, business logic, API routes, validation and error handling. Use when adding or changing API endpoints, services, validation or server-side error handling. |
| `/anthropica-engineering:frontend-development` | Implement or modify frontend UI, components, state, accessibility and responsive behaviour using the existing project conventions. Use when building or changing UI components, pages or client-side state. |
| `/anthropica-engineering:database-engineering` | Review or change SQL schemas, migrations, indexes, transactions and data-access code. Use when writing migrations, changing a schema, tuning queries or reviewing data-access code. |
| `/anthropica-engineering:testing-validation` | Design and run focused unit, integration, end-to-end and regression checks for a requested change. Use after implementing a change, or when tests are missing, flaky or failing. |
| `/anthropica-engineering:performance-investigation` | Investigate measured performance, latency, memory, database or frontend bottlenecks without speculative optimisation. Use when something is slow or memory-heavy and the cause has not been measured yet. |
| `/anthropica-engineering:security-review` | Review application changes for authentication, authorisation, input validation, secrets, injection and common security weaknesses. Use when a change touches authentication, user input, secrets, file handling or external integrations. |
| `/anthropica-engineering:github-commits` | Write and organise Git commits to industry standard (Conventional Commits, atomic changes, clear messages, correct identity, no secrets). Use when staging, committing, amending, splitting or rewording commits, or when cleaning up history before a push. |
| `/anthropica-engineering:github-pull-requests` | Create, review and merge GitHub pull requests to industry standard (branch naming, small focused PRs, clear descriptions, CI gates, review etiquette, merge strategy). Use when starting a branch, opening or updating a PR, responding to review, or merging. |
| `/anthropica-engineering:token-efficiency` | Reduce unnecessary Claude context and output while preserving correctness. Use when planning a Claude session, reducing token use, managing context, splitting work, or improving prompt efficiency. |
| `/anthropica-engineering:prompt-engineering` | Create precise prompts and task specifications for Claude and coding agents. Use when a task is ambiguous, complex, multi-stage, or needs clear acceptance criteria and bounded scope. |
| `/anthropica-engineering:technical-documentation` | Write or update concise technical documentation, setup guides, architecture notes and operational runbooks. Use when writing READMEs, setup guides, architecture notes or runbooks. |

## Agents

| Agent | Role |
|---|---|
| `architect` | Evaluates system design, boundaries, data flow, trade-offs and phased implementation plans. Use for design decisions, migrations or features that span several modules, before any code is written. |
| `code-reviewer` | Reviews a diff for correctness, regressions, maintainability and test gaps. Use after a change is implemented and before it is committed or merged. |
| `test-engineer` | Designs, writes and runs focused tests for changed behaviour, regressions and edge cases. Use after implementing a change or when tests are missing, flaky or failing. |
