# Format structures

Character limits are in `channel-limits.md`. Each structure below is a default; drop sections the reader doesn't need.

## Landing page
1. **Hero:** headline (outcome, matches the ad/email promise), subhead (how, for whom, in one line), primary CTA, risk reducer, one proof element (logo strip, rating, metric - all real).
2. **Problem:** the reader's situation in their words (2-4 lines).
3. **Benefits:** 3-5 blocks, each = benefit headline + 1-2 lines + supporting feature/visual.
4. **How it works:** 3 steps, numbered.
5. **Proof:** testimonial with name, role, photo (permissioned), case-study metric, certifications.
6. **Objections/FAQ:** price, effort to switch, security, contract, support - answer the top 4-6 from sales/support data.
7. **Offer recap and CTA** repeated; same wording as the hero CTA.
- One goal per page; remove global nav on paid-traffic pages if the brief allows.
- Above the fold on mobile: headline, subhead, CTA.
- Forms: ask only for fields used in the next step; every extra field costs conversions.

## Email
- **Subject + preheader:** read as a pair; subject hooks, preheader extends.
- **Opening line:** about the reader, not the sender ("You asked..." beats "We are excited to announce...").
- **Body:** one idea, 50-150 words for promotional, longer only for newsletters/nurture.
- **CTA:** one primary button (bulletproof HTML button, not image-only), repeated as a text link for long emails.
- **Plain-text version** that reads well on its own.
- **Footer:** sender identity, postal address where required, unsubscribe, why they're receiving it.
- **Sequences:** state each email's job (welcome -> value -> proof -> offer -> last chance) and the exit condition (converted, unsubscribed).
- Cold outreach: under ~120 words, one specific reason for contacting this person, one low-friction ask.

## Search ads
- Headline set: keyword theme (3-5), benefit (3-4), proof (2-3), offer/CTA (2-3), brand (1-2).
- Descriptions: expand the benefit + proof + CTA; each must stand alone.
- Match the landing page's headline promise.

## Social and display ads
- Hook in first line/first 3 seconds: a specific pain, a surprising number (sourced), or the outcome.
- Visual carries the message with sound off; on-image text minimal.
- One CTA aligned with the platform button.
- Variant set: 3 hooks x 1 body x 1 CTA is a cleaner test than 3 completely different ads.

## Organic social post
- First line works alone (before truncation).
- Short lines, white space, one takeaway, one ask (comment, click, share).
- Links: some feeds down-rank outbound links; follow the brief on whether to put the link in the post or a comment.
- Hashtags: 0-5 relevant, CamelCase.

## Product announcement / release post
1. Headline: what the reader can now do (not the feature name).
2. One-paragraph summary: who it's for, the problem it solves, availability (plans, regions, date).
3. How it works (steps or short demo).
4. Proof or example.
5. How to get it + CTA; link to docs.
6. What's next (only if committed).
- Avoid roadmap promises and dates that aren't approved.

## Push and SMS
- Lead with the value or the action required; personalise only with data the user knowingly gave.
- Time-zone aware sending; respect quiet hours.
- SMS: brand name first, opt-out instruction, no link shorteners that look like phishing; use the brand's own domain.

## Variant naming
`<asset>-<element>-<variant>` (for example `lp-headline-b`), matching `utm_content` so results can be joined.
